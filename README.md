# Formancy Report

**Paginated PDF reports, and Word files of them, designed inside your Angular or React application.**

Formancy Report is a paid, [source-available](#licence-in-one-table) module
for the documents a business sends: quotations, invoices paid by a Swiss
QR-bill or an EPC QR code, e-invoices, order confirmations, data sheets,
payment reminders, sales reports with charts. A person designs them inside
your application, and your application prints them from its own data. It
builds on the Apache-2.0 [formancy](https://github.com/sharkysan/formancy.ai)
packages; you host it, and you hand it the data.

## What it does

- **Design inside your application**, in a native React or Angular builder over one session, with undo, told what is wrong before anything renders ([0012](./docs/decisions/0012-the-builders-are-native-and-share-one-session.md), [0009](./docs/decisions/0009-an-expression-is-checked-and-bound-member-by-member.md)).
- **Print exact PDFs**, in Node or in a browser: totals exact and rounded once, values formatted for the report's language, and a report that cannot be drawn whole refused, never cut ([0010](./docs/decisions/0010-the-runtime-resolves-a-report-into-a-renderer-neutral-document.md), [0011](./docs/decisions/0011-report-render-pdf-draws-the-document-and-refuses-what-it-cannot.md)).
- **Write Word files** of the same document, which a person can go on editing: Word lays out their lines and pages, and what belongs to the PDF alone is refused, never left out ([0068](./docs/decisions/0068-a-report-is-written-as-a-word-file-by-a-writer-of-its-own-and-what-belongs-to-its-pdf-is-refused.md)).
- **Get paid by code**: a Swiss QR-bill and an EPC QR code for a SEPA transfer, held to SIX's and the EPC's rules and edited field by field in either builder ([0022](./docs/decisions/0022-a-report-carries-one-swiss-qr-bill-at-the-foot-of-its-last-page.md), [0025](./docs/decisions/0025-a-report-prints-an-epc-qr-code-held-to-the-epc-rules-beside-the-qr-bill.md), [0039](./docs/decisions/0039-a-person-selects-a-reports-qr-bill-and-edits-it-field-by-field-in-either-builder.md)).
- **Issue e-invoices**: a Factur-X / ZUGFeRD PDF/A-3b that embeds its EN 16931 XML, or an XRechnung 3.0 whose XML your application takes and sends; Report sends nothing. Mustang and KoSIT's validator judge the repository's e-invoice XML, and veraPDF and Mustang its Factur-X PDFs. France is not claimed ([0027](./docs/decisions/0027-a-report-carries-one-en-16931-invoice-written-from-the-values-its-page-prints.md), [0031](./docs/decisions/0031-an-e-invoice-is-drawn-as-a-pdf-a-3b-that-embeds-its-xml.md), [0038](./docs/decisions/0038-a-reports-e-invoice-may-be-an-xrechnung-3-0-whose-xml-a-host-takes-and-whose-pdf-is-its-labelled-copy.md)).
- **Archive as PDF/A-2b** any report that is no e-invoice, where your application asks; what a PDF/A cannot hold -- a CMYK JPEG, an SVG past its bounds, a title holding `&`, `<` or `>` -- is refused at that render ([0057](./docs/decisions/0057-a-report-that-is-no-e-invoice-is-drawn-as-a-pdf-a-2b-where-the-host-asks-for-one.md)).
- **Chart it**: bar, line and pie charts of the detail rows, totalled as the tables are and laid out by Apache ECharts, not yet in the builders' palettes ([0052](./docs/decisions/0052-a-report-draws-a-bar-line-or-pie-chart-of-its-detail-rows-each-series-a-total-of-one-field-per-category.md), [0058](./docs/decisions/0058-the-renderer-lays-a-chart-out-with-apache-echarts-and-prints-its-marks-and-its-words-where-echarts-placed-them.md)).
- **One template, several languages**: a render prints in the one it names, and a word missing there refuses it ([0063](./docs/decisions/0063-a-reports-own-words-are-written-in-each-language-it-declares-and-a-render-names-the-one-it-prints-in.md)).
- **Lay it out**: several tables over one list of lines, group headers kept with their rows, a first page of its own, text set above or below the line, fonts your application approves, pinned by digest, and SVG logos made of shapes alone -- no text, no embedded picture ([0062](./docs/decisions/0062-a-report-holds-several-tables-over-its-detail-rows-each-printing-and-totalling-the-rows-its-condition-selects.md), [0060](./docs/decisions/0060-a-reports-first-page-may-print-a-header-of-its-own-or-none-in-place-of-the-page-header.md), [0061](./docs/decisions/0061-a-paragraphs-run-may-be-set-below-or-above-the-line-in-any-character-its-face-draws-and-prints-only-beside-a-run-on-the-line.md), [0043](./docs/decisions/0043-a-report-maps-its-font-tokens-to-fonts-the-host-approved-pinned-by-digest-and-the-renderer-embeds-them.md), [0030](./docs/decisions/0030-an-image-asset-may-be-an-svg-of-drawing-elements-alone-cleaned-once-and-refused-at-print-in-any-other-form.md)).
- **Read your data where it lives**: your application's JSON, a formancy form's submissions, each against the form version that collected it, or a Formancy Data 0.5.0 server, best-effort ([0042](./docs/decisions/0042-a-report-reads-a-formancy-forms-submissions-against-the-exact-version-that-collected-them-as-the-host-hands-them-over.md), [0016](./docs/decisions/0016-the-data-provider-reads-formancy-data-0-1-0-best-effort.md)).
- **Let a coding agent work against Report's checks**: an MCP server, run by the agent's client, that describes the format and the commands, judges a report as the validator and a render would, within the size a draft may have, and applies commands as the builders do; it needs no server, and saves, publishes and fetches nothing ([0088](./docs/decisions/0088-an-agent-gets-reports-checks-over-the-model-context-protocol-from-a-server-of-reports-own.md)).
- **Keep drafts on a server**: it verifies your application's token offline and keeps each tenant's template drafts and images; it renders nothing yet ([0046](./docs/decisions/0046-report-has-a-server-of-its-own-over-the-hosts-verified-identity.md), [0049](./docs/decisions/0049-a-templates-draft-is-kept-by-the-report-server-one-per-tenant-saved-by-compare-and-swap.md)).

What is planned next, and what is not planned at all, is in
[the roadmap](./docs/roadmap.md).

## Try it

The Studio is online at https://formancy.ai/report/, and runs from a clone
with Node 22.13 or later and corepack:

```bash
git clone https://github.com/sharkysan/formancy.ai-report.git
cd formancy.ai-report
corepack enable pnpm
pnpm install
pnpm demo
```

`pnpm demo` builds the packages and the Studio, then serves it at
http://localhost:4394. It opens on the invoice, whose Swiss QR-bill is at
the foot of its page
([0082](./docs/decisions/0082-the-studio-opens-on-the-invoice-and-lists-it-first-and-the-corpus-keeps-its-order.md)).
Pick another starter or a blank report, edit it in either
builder, and download what the Preview prints. The starters' data is
synthetic and built in, and the page asks no other site for anything, which
the browser gate holds
([0023](./docs/decisions/0023-the-studio-and-the-pages-serve-their-own-faces-and-ask-no-other-site-for-anything.md)).
The online Studio is `main`'s, deployed on every push to `main`, so it can
be ahead of the latest release
([RELEASING.md](./RELEASING.md#the-demo-on-formancyai)); the product's
pages stand beside it, from https://formancy.ai/report/en/, in German,
French, Italian and English, with a page for each topic the start page
introduces
([0081](./docs/decisions/0081-the-start-page-names-pdf-and-word-pages-for-invoices-word-files-and-each-report-designer-join-it-and-every-package-names-keywords.md)).

## How it fits together

![A hand-drawn sketch of Formancy Report's packages on a dark background, in four columns, Edit, Print, Data in and Serve: the Studio and the product pages at the top; the MCP server for a coding agent below them; the builders, the two renderers, the test support, the form bridge, the data provider, the server and its client below that; then report-builder-core, report-runtime and report-server-core; report-ai, the model's turn; report-core; and report-spec and report-documents at the bottom. The editing column is violet, the printing column teal, and what is never published is dashed](docs/images/architecture.svg)

A report is a document of its own, versioned and validated by
`report-spec`. `report-core` changes it by commands with undo, and both
builders edit that one session. `report-runtime` resolves it against your
data, deciding every value once, and two engines print the result:
`report-render-pdf` as a PDF and `report-render-docx` as a Word file. Each
package depends only on those drawn below it, which
`scripts/architecture.test.mjs` holds to the manifests. `report-mcp`
gives a coding agent the same checks and commands over the Model Context
Protocol. [The architecture](./docs/README.md) says the rest.

## Render a report

Your application resolves a report against the data it may show, then
renders it. Nothing here fetches data or follows an address: the report
names its datasets and assets, and your application hands over both. Here
`report` is the quotation starter, `data` its synthetic data and `logo` its
mark's bytes and digest:

```ts
import { resolveReport } from '@formancy/report-runtime'
import type { ImageResolver } from '@formancy/report-runtime'
import { renderPdf, RenderRefusal } from '@formancy/report-render-pdf'

const images: ImageResolver = (ref) => (ref.asset === 'logo' && ref.digest === logo.digest ? { mediaType: 'image/svg+xml', bytes: logo.bytes } : undefined)
const resolution = resolveReport(report, data, { mode: 'final', parameters: {}, images, creationDate: '2026-10-15T08:00:00Z' })
if (!resolution.ok) throw new Error(resolution.errors.map((error) => `${error.code} at ${error.path}`).join('; '))
const pdf: Uint8Array = await renderPdf(resolution.document, { maxPages: 50 })
```

`resolveReport` refuses with every reason at once, and `renderPdf` rejects
with a `RenderRefusal` whose `code` says what stopped it; neither returns
part of a document. `renderDocx(resolution.document)`, from
`@formancy/report-render-docx`, writes the same document as a Word file.
The install gate runs these lines from the packed packages
(`scripts/install-fixture/consume.ts`).

## How it relates to formancy.ai and Formancy Data

Report depends on the released `@formancy/*` packages at exact versions and
copies none of their code
([0002](./docs/decisions/0002-depend-on-upstream-never-copy-it.md)), but
for formancy's model turn, which formancy does not export: `@formancy/report-ai`
holds it in formancy's shapes, held to formancy 0.14.0's by a test, until
formancy releases one other products may brief
([0083](./docs/decisions/0083-the-models-turn-is-held-in-report-ai-in-formancys-shapes-until-formancy-releases-one-other-products-may-brief.md)).
Formancy Data is optional: one package reads its records as the person whose
token your application supplies
([0016](./docs/decisions/0016-the-data-provider-reads-formancy-data-0-1-0-best-effort.md)),
and the report server verifies tokens with Data's `@formancy/data-identity`,
so running either in production needs a Data licence too
([0047](./docs/decisions/0047-report-server-verifies-the-hosts-token-with-formancy-datas-data-identity-0-3-0.md)).
A formancy form's submissions are read by a package that depends on
formancy alone
([0042](./docs/decisions/0042-a-report-reads-a-formancy-forms-submissions-against-the-exact-version-that-collected-them-as-the-host-hands-them-over.md)).

## Development

Node 22.13 or later, which `pdfjs-dist` 6.4 needs, and pnpm through corepack.

```bash
corepack enable pnpm
pnpm install
pnpm build
pnpm test
pnpm lint        # after pnpm build: the type-aware rules read the built declarations
pnpm format      # Prettier, over every TypeScript and JavaScript file, twice before committing: it is not idempotent on some member chains
```

CI fails a TypeScript or JavaScript file that breaks a lint rule or that
Prettier would write otherwise, by the four formancy repositories' shared
`@formancy/code-style`
([0050](./docs/decisions/0050-every-typescript-and-javascript-file-is-linted-and-formatted-by-the-rules-the-four-repositories-share.md));
a branch begun before the format takes `main` as
[`CONTRIBUTING.md`](./CONTRIBUTING.md#a-branch-begun-before-the-format)
says. `pnpm --filter @formancy/report-studio dev` serves the Studio on port
4394 once `pnpm build` has built the packages. CI runs the gates of
`.github/workflows/gates.yml` on every pull request and before a release,
and every run ends in a release report
([0014](./docs/decisions/0014-a-release-report-is-derived-from-the-run-that-gated-it.md));
[`CLAUDE.md`](./CLAUDE.md) gives each gate's command, and
[Verification](./docs/architecture/10-verification.md) what each proves.
